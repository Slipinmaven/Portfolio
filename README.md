# Portfolio API

An API backend for managing a professional portfolio. It provides public project and technology endpoints alongside authenticated administration, with FastAPI, PostgreSQL, SQLAlchemy, and Alembic.

This repository currently contains the backend service; there is no frontend application in this repository.

## Features

- Public listing and detail endpoints for published projects and technologies.
- Admin project management, including publishing and unpublishing projects.
- Admin technology management.
- Admin authentication with access and refresh tokens.
- Async database access, versioned Alembic migrations, and structured request logging.
- API documentation generated by FastAPI.

## Requirements

- Python 3.12
- PostgreSQL for running the API

The test suite uses an in-memory SQLite database and does not require a running PostgreSQL server.

## Quick Start

From the repository root, create a virtual environment and install the backend:

### Windows PowerShell

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
```

### macOS / Linux

```sh
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
```

Edit `backend/.env` and set a working PostgreSQL `DATABASE_URL` and a unique `JWT_SECRET_KEY`. Keep real credentials in `.env`; never commit them. Production requires a JWT secret of at least 32 characters and rejects the development secret.

Run database migrations and start the API from the `backend` directory:

```sh
alembic upgrade head
uvicorn app.main:app --reload
```

Open the interactive API documentation at <http://127.0.0.1:8000/docs>. The health endpoint is `/health`.

To create the first administrator, run this from `backend` after applying migrations:

```sh
python scripts/create_admin.py
```

The script prompts for credentials when bootstrap environment variables are not set. Alternatively, configure `BOOTSTRAP_ADMIN_EMAIL` and `BOOTSTRAP_ADMIN_PASSWORD` in the local environment before running it.

## API Overview

| Area                      | Routes                                                                        | Access                          |
| ------------------------- | ----------------------------------------------------------------------------- | ------------------------------- |
| Health                    | `GET /health`                                                                 | Public                          |
| Authentication            | `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`, `GET /auth/me` | Mixed                           |
| Projects                  | `GET /projects`, `GET /projects/{slug}`                                       | Public, published projects only |
| Project administration    | `/projects/admin` and project publish/unpublish actions                       | Admin                           |
| Technologies              | `GET /technologies`, `GET /technologies/{slug}`                               | Public                          |
| Technology administration | `/technologies/admin`                                                         | Admin                           |

See the interactive API documentation for request and response schemas and the complete route definitions.

## Development

Run the tests from `backend`:

```sh
pytest
```

Create a new migration when changing the database schema, then apply it with `alembic upgrade head`. Application startup does not create database tables automatically.

The backend follows this dependency direction:

```text
Endpoint -> Service -> Repository -> Database
```

See [backend architecture notes](backend/docs/architecture/backend-architecture.md) for more detail and [backend setup notes](backend/README.md) for dependency descriptions.

## Configuration

Runtime settings are loaded from `backend/.env` or the process environment. The available development defaults are documented in [`backend/.env.example`](backend/.env.example). Important settings include:

- `DATABASE_URL`: PostgreSQL connection URL using the `postgresql+asyncpg` driver.
- `JWT_SECRET_KEY`: secret used to sign tokens; use a unique value outside local development.
- `CORS_ORIGINS`: comma-separated allowed browser origins.
- `APP_ENV` and `DEBUG`: environment and debug mode.
